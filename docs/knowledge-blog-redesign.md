# 从文章流到知识目录：Blog 改版记录

日期：2026-09-05。本轮仅本地修改，未提交、推送或部署。

## 设计出发点

记录 AI 浪潮下的随想与观察，聚焦思考、沉淀与实践。站点不以热点、热度或更新频率决定阅读价值，而是帮助读者找到问题、逐步深入，并回访自己的理解。

沿用暖纸色、宋体标题、深浅主题与原有 Astro 技术栈。首页不再平铺全部文章，也不为每篇文字制造重复的封面卡片。没有添加框架或依赖，没有修改本轮之前的文章正文、原 slug 或评论 page key。

## 阅读结构

| 层级 | 入口 | 解决的问题 |
| --- | --- | --- |
| 首页 | `/` | 这里关心什么？可以从哪里开始？ |
| 知识目录 | `/topics/` | 技术与系统、产品与实践、认知与观察之间的关系 |
| 阅读方向 | `/topics/{id}/` | 此方向有哪些系列和独立观察？ |
| 系列目录 | `/series/`、`/series/{id}/` | 阅读目标、总览—实践—思考、章节顺序 |
| 文章 | 保留 `/writing/{id}/` | 当前章节、系列目录、本篇目录、前后篇 |
| 完整归档 | `/library/` | 关键词检索、组合筛选、排序、分页 |
| 随想与时间线 | `/notes/`、`/timeline/` | 不要求每个想法都成为系列，保留时间视角 |

当前接入 7 个系列、36 篇系列章节；站内共 48 篇记录。此前六篇拆稿构成 31 篇，另有原来的万级能力路由五篇。首页“最近修订”按系列合并，仅显示六条，避免批量拆篇占满入口。相同日期的顺序只用于稳定展示，不表示价值排名。

三条主线是编辑组织方式，不是硬性的知识边界。系列有一个主归属；独立文章根据标签可以出现在多个方向中，因此方向篇数不应简单相加当作全站篇数。没有匹配主线标签的新文章仍会进入完整归档，不会消失。

## 后续如何维护

1. 新增文章：仍在 `src/content/writing/` 写 Markdown 和原有 frontmatter；构建后自动进入归档、标签索引与适用的阅读方向。
2. 新增系列：在 `src/data/knowledge.json` 的 `series` 登记稳定 ID、主方向、简介、阅读目标、贯穿问题和按顺序排列的文章 ID。标题、修订日期和阅读时间直接读取文章，不复制维护。
3. 调整阅读方向：修改同一文件中的 `topics` 与标签映射。不要仅为了新建一个标签，就增加顶层导航。
4. 首页精选：在 `src/pages/index.astro` 的 `featured` 中选择系列 ID；这是一项编辑选择，不是热度推荐算法。
5. 旧入口：`/essays/` 导向 `/library/?type=essay`；所有原文章 URL 保留。

构建会拒绝重复目录 ID、未知主题、缺失章节、同一文章重复注册，以及少于三篇的系列。文章 Markdown 原有的系列导航保持可移植；仅当首块完整匹配已登记章节时，页面隐藏重复导航，由站点的桌面侧栏和手机折叠目录接替。

## 搜索与增长边界

- 当前为本地元数据检索：标题、摘要、标签、系列名；不是正文全文检索，不做语义搜索。
- 多关键词以空格分隔，采用全部匹配；支持大小写和全角字符归一化。
- 方向、系列、标签、类型、内容范围可以组合筛选；选中系列且使用默认排序时按章节排列。
- 筛选条件写入 URL，支持分享、刷新恢复和浏览器后退；未知筛选显示为空结果，允许一键清除。
- 每页 12 篇，浏览器只生成当页结果节点。静态分页在禁用 JavaScript 时仍可浏览所有文章；搜索与筛选需要 JavaScript。
- 归档页携带全部文章的轻量元数据，不携带正文。随着内容增长应观察索引体积与输入响应，再决定是否引入分片索引或全文搜索。此次没有宣称已完成万篇性能压测，也没有引入搜索后端。
- 未加入登录、阅读追踪或假阅读进度；“第几篇”指所在章节，不代表读者已经读完多少。

复核浏览器时，使用现有 Playwright 安装，并通过环境变量指定其包目录及预览 URL：

```sh
BLOG_PLAYWRIGHT_ROOT=/absolute/path/to/node_modules \
BLOG_BASE_URL=http://127.0.0.1:4322 \
node scripts/knowledge-browser-check.mjs
```

单元测试使用支持原生 TypeScript 类型剥离的 Node 版本（本轮为 Node 26）。生产构建不要求浏览器测试依赖。原开发服务保持不变，本轮生产预览供本地 Review。
