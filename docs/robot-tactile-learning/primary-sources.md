# 触觉学习视频：一手研究核查

核查日期：2026-10-28。正文写作支持，不是视频逐字稿。优先使用以下论文和作者项目，所有结果均属研究团队报告，未由本任务独立复验。

## 1. T-Rex：正文最重要的研究锚点

- 原论文：Niu et al., **T-Rex: Tactile-Reactive Dexterous Manipulation**，2026-06-15，固定v1：[HTML](https://arxiv.org/html/2606.17055v1)、[摘要](https://arxiv.org/abs/2606.17055)。
- 作者项目：[tactile-reactive-dexterous.github.io](https://tactile-reactive-dexterous.github.io/)。当前代码：[ZhuoyangLiu2005/T-Rex](https://github.com/ZhuoyangLiu2005/T-Rex)。项目和代码可能晚于论文更新，不能混称原始发布材料。

### 机制与数据

原论文第4节提出三个专家：latent expert学习未来视觉表示，action expert生成较慢的动作计划，tactile expert用新触觉信息细化动作。Flow matching采样过程被拆成两段：先做重计算的视觉/语言条件动作生成，缓存中间结果，再用轻量触觉专家继续完成后段采样；不必每次触觉更新都重跑视觉堆栈。这是在学习策略内耦合快慢通路，不宜写成两个完全独立、互不通信的系统。

触觉编码结合最近16帧力/力矩历史的VQ-VAE表示、当前原始力向量和形变图特征。VQ-VAE是压缩时序的一种实现，并不是它天然消除了漂移。论文仍在局限章节列出传感器失真、设备间标定漂移、缺少密集掌部感知。

作者项目将动作/触觉两路标作约5 Hz/20 Hz；正文若无必要，写“触觉更新更快”即可。不要写成毫秒级实测端到端延迟，更不要把它等同于300 Hz底层控制线程。原论文附录D描述30 Hz高层遥操作、300 Hz底层控制；这不是所有模型分支都达到300 Hz。

训练是三阶段：人类第一视角预训练（论文22,889小时）→ 100小时同步触觉机器人中训练 → 目标任务后训练。100小时数据覆盖200多物体、22类操作原语；不是100小时从零训练全部智能，更不是通用规模定律。当前仓库明确公开的是约50小时子集，论文/项目摘要说100小时数据集，正文应区分“收集/使用”和“可下载”的规模。若不讨论开放细节，只写研究使用100小时。

### 最应保留的证据口径

原论文第5.1节每任务16次随机初始位置与朝向评测，表1共12任务。作者把指标称success rate，但明确多阶段任务使用进度/部分完成评分；附录F详细列加权子步骤。

| 原论文表1方法 | 作者报告平均指标 |
| --- | --- |
| π₀.₅ | 17 |
| π₀.₅ + tactile | 6 |
| EgoScale | 35 |
| T-Rex | 65 |

**不要把65直接写成“65%的任务从头到尾完整成功”。** 可以写“按作者含部分完成计分的评测口径，平均得分由35提升至65（百分制口径）”。差是30个百分点，不是相对提高30%；表中四舍五入数据不支持更精确比例。

π₀.₅+tactile的实现见附录E：在原state输入上拼接10根手指单时刻6维力/力矩向量，从公开检查点微调。它验证的是这种融合与训练设置可能变差，不是“π₀.₅只要有触觉就变差”，也不证明所有早期融合都无效。

表2是在**6个代表任务**上的消融：完整模型65；去掉触觉42；去掉异步机制60。不能把6任务消融和12任务主比较当作同一批样本；不应据5分差直接推出所有收益来自异步。数据、预训练、编码、模型容量一起参与效果。

论文局限：长程精密接触与严格公差任务仍困难，存在硬件失真、跨设备漂移、掌部覆盖缺口。结果不是长期生产可靠性或跨任意传感器泛化证明。

## 2. DIGIT：光学触觉图像不是外部相机看物体

作者官方页：[DIGIT](https://digit.ml/digit.html)；[2020年论文](https://arxiv.org/abs/2005.14679)。作者说明传感器以图像形式感知接触物体的几何，能由图像估计法向力，结合标记可以估计剪切力。这支持“把接触变形变成可处理的光学信号”，不支持“原始像素就是未经标定的绝对力”。体积小、制造一致性和耐用性是设计目标，性能仍按具体传感器检查。

## 3. GelSight：弹性体与接触表面形状

MIT作者资料：[GelSight](https://people.csail.mit.edu/kimo/gelsight/)；厂商技术页：[GelSight technology](https://www.gelsight.com/tactile-sensing-technology/)。软弹性体贴合接触表面，成像得到高分辨率形状/纹理信息。这里的关键是局部接触形变和照明几何，而不是让普通外部视觉无代价获得接触力。厂商“精确”“不受光照/反射影响”等宣传应保留具体系统适用范围，正文无需引用最高性能承诺。

## 4. Sparsh：自监督触觉表征，不是通用控制策略

[原论文](https://arxiv.org/abs/2410.24090)、[作者项目](https://sparsh-ssl.github.io/)、[官方代码](https://github.com/facebookresearch/sparsh)。2024年工作使用46万多张触觉图像进行自监督预训练，面向DIGIT/GelSight类视觉触觉传感器。TacBench覆盖力估计、滑动检测、姿态等下游任务。

可用于解释“未标注触觉也能学有用表示，但任务头和闭环控制仍需验证”。不要把TacBench平均相对提升95.1%写成机器人成功率95.1%，也不要写全部下游任务完全不需要标签。正文已有T-Rex主线，Sparsh只需一句机制补充或进一步阅读。

## 5. AnyTouch：跨传感器对齐有具体的数据条件

[作者项目](https://gewu-lab.github.io/AnyTouch/)、[ICLR2025论文](https://openreview.net/pdf?id=XToAemis1h)。研究静态和动态的跨视觉触觉传感器统一表示，TacQuad包含四种传感器的对齐记录；细粒度数据要求同物体同位置同速度，粗粒度数据不保证时间对齐。

可支持“跨传感器表示是一项需要配对/对齐数据与方法的研究问题”，不能推出任意触觉设备已即插即用。不必扩写为第二条模型史，避免偏离视频。

## 6. Meta官方概述：多种触觉信号和局部反馈的方向

[2024-10-31官方公告](https://ai.meta.com/blog/fair-robotics-open-source/)。同时介绍Sparsh、Digit360和Digit Plexus，分别是表征、传感硬件和集成平台。应区分三层，不能因为用了共同品牌，就把传感器指标当模型性能。仅作为补充阅读；“human-level”等厂商用语不能当作全任务对等的独立证明。

## 可转为正文学习问答的结论

1. **触觉加入后指标下降，说明触觉没用吗？** 不。增加信号改变输入分布和学习难度；单帧拼接可能丢失时序，模型可能无法及时利用新信号。T-Rex比较支持特定融合方式不够好，更强因果结论需同训练预算的消融。
2. **高频反射与语义控制二选一吗？** 不。局部接触变化决定何时快速修正；任务语义决定希望达到什么状态。合理系统可分速率处理并让局部修正受任务与约束影响。T-Rex是具体实现之一，不是唯一正确架构。
3. **触觉只需10万小时、视觉需要100万小时是定律吗？** 不是；视频嘉宾预期不能替代同任务、同模型、同覆盖和同算力控制下的学习曲线。帧数、接触事件数、轨迹数和小时数也不能直接互换。
4. **人类采集设备记录了触觉，就能直接迁移到机器人吗？** 不。皮肤/弹性体、手指几何、载荷、接触位置、采样频率和动作执行不同；需要映射与目标身体验证。T-Rex人类视频预训练之后仍使用同步机器人触觉中训练，正说明两层信息不同。
