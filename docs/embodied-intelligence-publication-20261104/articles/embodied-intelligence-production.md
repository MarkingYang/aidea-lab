# 具身智能：从能力演示到可持续生产力

机器人在视频中完成一次任务，与在客户现场稳定创造价值之间，隔着可靠性、学习效率和完整成本。把这三个问题连接起来，才能理解模型进步怎样成为生产力。

**研究基准：2026 年 9 月 13 日。** 本文结合访谈整理稿与公开研究；受访者判断、技术实验和假设算例分别表述。录音保存日期不等于节目首发日期，本文也不把访谈中的阶段性结论当作行业现状。

## 先把问题拆成三层

**核心问题是：具身智能如何把不断提升的模型能力，转化为真实环境中可持续、可复制且成本成立的任务交付。竞争优势取决于三个环节能否相互促进：可靠执行任务、从执行中学习、把学习成果转化为客户价值。**

这意味着，评估一家企业应同时观察：每完成一项合格任务要付出多少总成本；每进入一个新场景需要多少新增适配；每一轮现场数据能带来多少经过验证的能力提升。

```text
中心判断：能持续降低任务交付成本，并把现场经验变成可复用能力，才有持久竞争力。
│
├─ 论点一｜能力成立：机器人必须在扰动下完成任务并处理失败。
│  ├─ 1.1 模型、身体与环境共同决定任务边界。
│  ├─ 1.2 触觉与实时反馈补足接触过程中的信息缺口。
│  └─ 1.3 多任务、跨场景与跨本体泛化必须分开验证。
│
├─ 论点二｜学习成立：真实反馈必须以可承受的成本转化为能力提升。
│  ├─ 2.1 不同数据解决不同问题，训练配方比单一规模重要。
│  ├─ 2.2 现场部署只有经过筛选、训练和验证才形成数据飞轮。
│  └─ 2.3 开源工具与统一评测降低迭代成本，但不会自动形成壁垒。
│
└─ 论点三｜生意成立：整个工作流必须有价值，并能复制交付。
   ├─ 3.1 场景选择要同时考虑能力、兜底成本和替代方案。
   ├─ 3.2 商业账以合格任务为单位，计入接管、停机和集成成本。
   └─ 3.3 从配置化交付走向通用能力，避免项目收入稀释研发。
```

三个分论点分别回答“能不能做、能不能越做越好、能不能持续卖”。它们按决策问题拆分，彼此有因果联系；其中任何一项长期不成立，都可能阻断规模化。

### 从行业进展回到交付问题

| 层次 | 内容 |
|---|---|
| S：背景 | 公开研究显示，机器人模型、触觉、仿真与开发工具均在推进，产业开始具备更多可组合的技术条件。 |
| C：冲突 | 演示效果、论文分数、出货数量与客户持续使用之间缺少直接对应关系；更强能力也可能伴随更高硬件、训练和运维成本。 |
| Q：问题 | 什么条件能让机器人从一次成功走向长期可用，并把商业落地转化为下一轮技术进步？ |
| A：回答 | 以具体任务为入口，把可靠执行、数据学习和经济交付三者做成相互促进的系统，再用未见场景检验可复制性。 |

## 一、能力成立：可靠性来自模型、身体与反馈的协同

### 1.1 “模型是瓶颈”与“系统整合是壁垒”可以同时成立

**中心判断：瓶颈取决于任务与工况，不能将整个行业归结为同一个短板。**

唐文斌在访谈约  强调，模型智能度限制了机器人完成任务；硬件访谈约  则强调，量产一致性、长期稳定性和系统整合难度。这两种判断观察的是不同层面：前者关注既有硬件能做却尚未自主做好的任务，后者关注同一套能力能否在多台机器和长期使用中稳定复现。[访谈节目][N-T]、[硬件节目][N-H]

把一个搬运或装配任务拆开，可以看到三类失败：

| 失败层 | 具体例子 | 优先检验的变量 |
|---|---|---|
| 物理不可达 | 手伸不进容器；末端无法夹持；连续载荷下过热 | 构型、末端工具、负载、热管理、工位设计 |
| 决策或控制失败 | 找错物体；选错抓取点；对准失败；滑动后未调整 | 感知、状态估计、策略、实时控制与传感反馈 |
| 系统运行失败 | 单机可用，换批次后漂移；线束磨损；维护导致长时间停机 | 标定、制造一致性、诊断、可维护性、备件体系 |

**分析推论：单件成熟并不推出系统成熟，硬件达标也不推出自主能力达标。** 当模型越来越强，先前被模型问题遮住的热管理、传感漂移和维护瓶颈，反而可能变得更突出。

访谈提出用遥操作判断硬件能否完成任务，这是有效的早期筛查：熟练操作者在相同观测与控制条件下能完成、模型不能完成，提示自主能力存在提升空间。但遥操作受延迟、控制接口和操作者熟练度影响，不能把“人遥操失败”直接等同于“任何算法都不可能成功”。[访谈约 ][N-T]

对人形也应采用相同判断。人形的潜在价值在于适应按人设计的工具、通道和工作空间；是否需要双足、双臂、灵巧手，要由任务覆盖带来的收益与额外成本共同决定。固定工位、轮式底盘、机械臂和专用夹具都可能是具身能力的载体。

**产品含义：先定义任务包与环境边界，再配置身体；用目标工况下的连续表现评估硬件。**

### 1.2 触觉的价值是让关键接触状态可被观测，并及时改变动作

**中心判断：触觉是否值得加入，要看它减少了哪些失败、提高了多少效率，以及新增了多少成本。**

视觉可以提供物体位置与形状信息，但在遮挡、滑移、柔性形变或插接过程中，一部分关键状态无法仅从图像稳定判断。触觉、关节力矩和本体感知提供互补信息。例如，抓取软包装时，目标不是机械地完成“闭合夹爪”，而是在不损坏包装的前提下保持抓持，并在滑移趋势出现时调整。[触觉节目][N-F]

这里有两个独立问题。第一，传感器有没有获得有效信息；第二，控制策略有没有在合适的时间使用这些信息。增加传感器可能同时带来同步误差、漂移和噪声，因此“多一个模态”不保证任务表现提升。

T-Rex 提供了一个具体研究例子：它使用不同速率的 Mixture-of-Transformers（MoT）与时序触觉编码，将触觉反应纳入策略。论文报告了约 100 小时触觉数据和 12 类操作任务实验。它支持“按模态时间特性设计架构”的方向，并不证明通用触觉基础模型已经完成。[T-Rex 论文](https://arxiv.org/abs/2606.17055)

可以把功能理解为三个时间尺度，但这只是分析框架，并非所有系统都必须使用三个独立模型或三颗芯片：

| 功能 | 回答的问题 | 重点约束 |
|---|---|---|
| 任务规划 | 要完成什么，下一阶段做什么？ | 目标理解、历史状态、任务分解 |
| 动作策略 | 接下来一段动作如何执行？ | 轨迹质量、观测更新、动作连续性 |
| 接触与底层控制 | 当前受力、位置和稳定性是否需要调整？ | 端到端延迟、抖动、闭环带宽、失效保护 |

**不能把动作轨迹的采样频率、模型重新推理的频率和电机控制频率混成一个指标。** 一次生成 50 个动作点，不代表模型根据最新视觉重新决策了 50 次。评估“快慢系统”时，真正要测的是从接触变化发生到实际动作纠正的完整延迟。

硬件选型同样需要具体化。视触觉适合研究精细接触形貌，但像素数不能直接换算成人类触觉能力，也不能单凭传感原理给出“精度最高”的总排名。应在目标任务中比较力分辨率、带宽、漂移、厚度、寿命、标定和计算成本。

建议采用同一硬件、同一任务分布下的三组对照：视觉与本体感知基线；加入触觉但不专门适配时序；加入触觉并适配融合与控制。这样才能区分信息增益、架构增益和新增计算量的作用。指标至少包括无人工合格完成率、任务时间、损坏率和接管时间。

**分析推论：触觉企业可能建立的长期优势，来自传感器、标定、耐久性、数据和控制适配的组合。高分辨率参数本身还不能证明客户愿意长期付费。**

### 1.3 技术路线应按可验证的设计选择比较

**中心判断：“学院派、巨头派、创业派、技术极致派”这类说法混用了组织类型与技术特点，不适合直接比较能力上限。**

更有解释力的是四个相互独立的维度：

| 维度 | 主要选择 | 需要验证的结果 |
|---|---|---|
| 知识从哪里来 | 复用预训练 VLM；更早混合具身数据；多任务联合训练 | 语义保持、动作学习效率、跨任务迁移 |
| 动作如何生成 | 离散表示；连续动作生成；动作块与在线纠正 | 精度、延迟、连续性、扰动响应 |
| 经验如何获得 | 示教、真机执行、仿真、视频及其组合 | 同等总预算下的真机增益 |
| 能力如何交付 | 整机集成、模型服务、工具平台、行业方案 | 适配成本、维护责任、客户收益和复用率 |

DM0 的公开论文描述了在 VLM 预训练阶段混合多类数据，再加入动作专家、采用后续训练和梯度处理的方案；π₀ 则展示了复用预训练 VLM 并生成连续动作的路线。二者都包含多阶段训练和工程设计，不能简化成“原生一定优于后装”。[DM0 论文](https://arxiv.org/abs/2602.14974)、[π₀ 官方技术说明](https://www.pi.website/blog/pi0)

**“具身原生”提出的是一种训练假设；其优势应通过同等预算和同类任务下的实验验证。** 训练起点不同，不等于长期能力上限已经分出胜负。

泛化也需要拆分：

| 评测 | 能证明什么 | 不能直接证明什么 |
|---|---|---|
| 单任务微调 | 学过这一任务后能达到什么表现 | 一套模型能处理很多任务 |
| 多任务单模型 | 同一模型能处理多个已训练任务 | 能完成从未见过的新任务 |
| 新对象、新场景 | 对某类分布变化具有适应性 | 其他维度也能泛化 |
| 新任务零样本 | 在明确未训练的新任务上有迁移能力 | 任意指令和任意环境均可用 |
| 新本体适配 | 经验能在不同机器人之间迁移 | 不需标定、不需动作映射或新增数据 |

访谈约  对 Specialist、Generalist 和 Zero-shot 作了明确区分。“Generalist 约三成”是该访谈语境下的结果，不能拿来代表整个行业，更不能当作截至整理日的最新成绩。[访谈节目][N-T]

长任务还会放大局部错误。假设任务必须连续完成 20 个步骤、任何一步失败都终止，且每步在此前成功条件下的成功概率均为 95%，则整项完成概率为 0.95²⁰≈35.8%；若每步为 99%，则为 81.8%。这是示意算例，不是实测行业水平。真实流程中的重试与恢复会改变结果。

**因此，通用能力的商业检验还包括：错误是否被识别，能否恢复，恢复是否足够快，以及整项任务最终是否按质量要求交付。**

## 二、学习成立：把真实经验转化为可复用能力

### 2.1 数据路线是按任务和训练阶段配置资源

**中心判断：“仿真为主还是实机为主”过于粗糙，必须追问在哪个任务、哪个训练阶段、以什么成本和效果计量。**

把机器人训练类比人类健身，适合说明策略学习通常不增加电机固有扭矩。但进一步写成“真机训练很少、绝大多数都在仿真完成”并不适用于全部机器人任务。仿真同样消耗算力和电力；真机示教、真机强化学习、部署后的数据采集，也都是不同的活动。Boston Dynamics 的官方材料明确介绍了 Atlas 的仿真强化学习，不能把它作为“纯真机健身房”路线的代表。[Atlas 训练说明](https://bostondynamics.com/blog/can-football-teach-a-robot-to-move/)

| 数据来源 | 主要价值 | 主要缺口 | 应采用的判断 |
|---|---|---|---|
| 互联网图文与视频 | 语义、物体关系、任务结构与行为先验 | 缺少与机器人动作、受力精确同步的观测 | 是否减少目标任务所需示教，是否改善新对象理解 |
| 人类第一视角与可穿戴数据 | 自然任务流程、操作覆盖 | 人机形态差异，动作与接触映射误差 | 转换后是否提升真机表现，采集装置是否改变操作 |
| 机器人示教 | 对齐观测、动作和目标硬件 | 采集费用、演示偏差、失败覆盖不足 | 有效片段密度、操作一致性和任务覆盖 |
| 物理仿真 | 可控试错、参数扰动、并行采样 | 接触、材料、传感和现实分布误差 | 在相同总预算下带来的真机效果 |
| 学习式世界模型 | 预测动作后果、生成候选未来、辅助训练 | 分布外失真，策略可能利用模型误差 | 预测能否指导真实决策，闭环训练收益能否复现 |
| 实际部署数据 | 真实故障、接管、业务扰动与使用分布 | 数据权限、标注、选择偏差、低信息重复 | 是否修复高频或高损失失败，并迁移到未见条件 |

**原力灵机案例需要按版本解释。** 完整访谈在约  明确表示当时以真机数据为主，并认为接触密集操作的仿真存在局限；官方 OpenDM 随后明确记录 DM0.5 于 2026-07-09 发布，OpenDW 也公开了动作条件世界模型。两者可体现技术演进，也可能讨论不同训练阶段，不能只依据录音保存日期判定其中一份“错误”。[访谈节目][N-T]、[OpenDM](https://github.com/dexmal/opendm)、[OpenDW](https://github.com/dexmal/opendw)

本次可确认新模型与公开实现存在，但未独立复现笔记中的“真机数据需求降低 60%、训练成本降低 40%”。这些比例不用于推导行业结论。OpenDW 的公开说明还注明 Value Expert 后续更新，公开仓库不能直接等同于公司全部内部训练链路已可复现。[OpenDW 架构说明](https://github.com/dexmal/opendw)

由此得到两个更深的判断：

**第一，预训练的数据来源与后训练的试错环境可以不同。** 大量真机示教用于获得可靠初始能力，再在学得的环境中优化策略，在逻辑上完全相容。后训练减少真机用量，也不意味着整个基础模型不再依赖真实数据。

**第二，数据扩张的目标应是单位总成本带来的真机能力增益。** 数据小时数需要经过有效性、多样性、同步质量和任务相关性的筛选。重复录下相同成功动作，未必比少量高信息接管片段更有用；只收集失败也不够，因为训练还需要正确动作或有效评价信号。

AI 社会模拟研究在这里提供了有价值的方法论：生成结果看起来合理，不能替代现实验证。但社会行为模拟、物理引擎和动作条件世界模型描述的对象不同，三者的结果不能互相充当能力证据。相关 1,052 人研究中的“85%”是相对于参与者自身重测一致性的归一化表现，并非能预测 85% 的所有人类行为。[原研究](https://arxiv.org/abs/2411.10109)

对世界模型而言，本次建议的验证顺序是：先测动作条件预测，再测候选动作排序，最后比较相同预算下训练出的策略在真机上的表现。只有最后一步成立，才说明模拟给任务交付带来了增益。

### 2.2 数据飞轮需要五个环节同时成立

**中心判断：部署量是获取经验的条件，学习效果才是数据飞轮转动的证据。**

访谈约  提出了机器人行业的循环难题：能力不成熟导致无法使用，无法使用又缺少高价值现场数据。解决办法是在边界明确的场景里通过系统兜底先运行起来，再让接管与失败反馈推动改进。[访谈节目][N-T]

```mermaid
flowchart LR
    A[真实任务运行] --> B[识别失败与接管]
    B --> C[筛选并对齐数据]
    C --> D[训练候选策略]
    D --> E[独立测试与小范围上线]
    E --> F[任务成本下降]
    F --> A
```

这条学习闭环把现场运行与版本更新连接起来；只有独立测试和实际成本改善同时成立，新增部署才形成可验证的学习收益。

| 环节 | 必要条件 | 常见断点 |
|---|---|---|
| 运行 | 有真实任务、持续时长和业务价值 | 机器只用于展示或数据采集，没有终端需求验证 |
| 回流 | 能记录失败前后状态及接管动作，有相应使用权限 | 只留下成功视频，或现场数据不能用于训练 |
| 整理 | 时间同步、版本记录、质量筛选与失败归因 | 多台设备的数据不可比较，错把硬件漂移当策略错误 |
| 学习 | 新数据改变策略在目标分布上的表现 | 堆积大量重复数据，旧任务遗忘，新任务过拟合 |
| 验证 | 未参与训练的数据和现场测试确认收益 | 只在训练任务重测，或用更多人工操作掩盖退步 |

**从“单场景千台”到“数据优势”还缺一段论证。** 千台是访谈中的业务目标，不是普遍阈值。少量机器人若覆盖关键物体与失败类型，也可能获得较高信息价值；大量机器人若都做同一种简单动作，边际学习价值可能快速降低。[访谈约 ][N-T]

应新增四个观测量：每千次任务中可用于训练的接管片段数；发现高损失失败到修复上线的周期；修复后未见场景的增益；同一故障在同等条件下的复发率。它们比单独报告“累计几万小时”更接近学习能力。

还有一项容易忽略的机制：被模型主动拒绝的任务，可能从训练数据中持续消失。应单独记录拒绝、人工转运和异常放弃的任务，否则“成功率提高”也可能只是接单范围缩小。

### 2.3 开源降低共同成本，竞争优势取决于复用与反馈机制

**中心判断：开源是资源组织和接口扩散的一种方式，其技术收益与商业收益需要分别验证。**

Open X-Embodiment 将多机器人数据组织成可共同使用的研究资源；LeRobot 提供数据采集、训练和部署相关工具；Dexbotic 是面向 VLA 的工具箱。它们各自降低不同环节的重复劳动。[Open X-Embodiment](https://arxiv.org/abs/2310.08864)、[LeRobot 文档](https://huggingface.co/docs/lerobot/index)、[Dexbotic 官方仓库](https://github.com/dexmal/dexbotic)

但应区分四个层次：代码能否使用、权重能否取得、训练能否复现、真实数据是否开放。OpenPI 已公开训练或微调相关代码，因此不能沿用“只有权重和推理代码”的概括；这仍不代表完整专有训练数据可得。[OpenPI 官方说明](https://github.com/Physical-Intelligence/openpi/blob/main/README.md)

从开源到竞争优势，要跨过两道门槛：

1. 外部采用是否真的降低内部适配成本，带来有质量的测试、贡献和人才；单纯下载或收藏不够。
2. 企业是否拥有客户愿意付费的交付能力，例如可靠部署、持续升级、硬件适配或维护服务；免费使用量不自动等于收入。

社区使用模型不会自动把现场数据交回模型公司。是否回流，取决于技术接口、协作激励和客户授权。因此“开源自然形成数据飞轮”只是待验证假设。

评测基础设施也具有类似的双重性。它可以缩短实验周期，但由参赛方运营的基准需要额外重视独立性：固定测试协议、披露微调预算与人工介入、保留未公开测试集，并接受第三方复现。公开代码有助于复现，无法单独消除针对基准优化的问题。

**产业推论：随着通用工具更易获取，企业需要证明自己的优势在未见任务、长期运行或低成本交付中仍然存在。** 工具开放会降低入场成本，也会促使竞争转向现场数据质量和产品工程。

## 三、生意成立：以完整工作流和合格任务计算价值

### 3.1 场景的容错性往往来自系统设计

**中心判断：可落地的场景通常需要可定义的任务边界、可承受的失败后果和可计量的经济收益。**

唐文斌提出错误容忍、时间容忍、适度泛化和长时间作业四个条件，并明确说它们是“必要不充分”的筛选条件。物流之所以在其策略中优先，是因为机器人无法完成时，可以通过调度转交人工，让整个工作流继续运行。[访谈约 ][N-T]

由此应把“物流容错高”改写为：**在允许缓冲、分流和人工兜底的物流子任务中，可以通过工程设计获得较高容错性。** 高速分拣、易碎品、危险品或强时限业务显然需要另行判断。

下表是本次提出的场景比较框架，属于条件判断，不是行业项目排名：

| 候选子任务 | 可能适合的条件 | 主要约束 | 必须比较的替代方案 |
|---|---|---|---|
| 带缓冲区的仓储拣选 | 商品有变化，可转人工，任务量稳定 | 遮挡、包装形变、订单高峰的接管排队 | 人工、专用分拣设备、已有抓取系统 |
| 线边备料或独立装配工位 | 可隔离测试，换型有价值，结果可检测 | 接触精度、质量要求、工位适配成本 | 夹具、传统机械臂、流程重排 |
| 标准设备上下料 | 动作范围明确，运行时间长 | 既有自动化可能已经更便宜可靠 | 专机、PLC 与视觉方案 |
| 家庭通用服务 | 有多样任务需求 | 物体与环境高度变化、低利用率、维护分散 | 家电、人工服务、限制任务范围的机器人 |
| 展示与娱乐 | 客户愿意为体验付费 | 复购逻辑与生产作业不同 | 展陈、演员、固定互动装置 |

汽车工厂包含很多性质不同的任务，不能从“主线节拍严、错误损失高”推导出所有汽车场景都不适合。娱乐也可能有独立商业价值；它对通用生产力学习是否有帮助，需要另行证明。

**场景选择至少跨两道门：先能经济地完成，再能从中学到可复用能力。** 前者决定能否生存，后者决定一家追求通用能力的企业能否借落地扩大优势。具体顺序与侧重应符合企业战略，不能要求每家零部件或垂直服务企业都做基础模型。

### 3.2 成功率只有放进单位经济模型才具有商业含义

**中心判断：客户购买的是合格产出。无人完成率影响人工成本，但整套系统能否按要求交付同样重要。**

建议在同一观测周期定义：

```text
单位合格任务成本
=（设备折旧或租赁 + 算力 + 能源耗材 + 维护
   + 人工兜底 + 集成摊销 + 返工及损失）/ 合格完成的任务数
```

直接用实际周期总成本和合格交付量计算时，停机对产量的影响已进入分母，不要重复扣减。若客户侧账中已经包含服务费，不能再把服务商同一项内部成本重复相加。供应商则应另算研发、售前、现场工程和服务履约后的利润。

为说明接管的作用，使用一个**假设算例，所有数字均非市场报价或企业实测**：

| 参数 | 假设值 |
|---|---:|
| 每开机小时分配的任务数 | 120 次 |
| 在计划小时中可用于接任务的比例 | 95% |
| 每计划小时任务量 | 114 次 |
| 单机每计划小时固定成本，含设备与必要服务摊销 | 30 元 |
| 每任务耗材与其他变动成本 | 0.01 元 |
| 每次转人工处理所需时间 | 2 分钟 |
| 人工成本 | 0.5 元/分钟 |
| 同质量、同边界的基准流程单位任务成本 | 0.40 元 |

假设所有机器人未自主完成的任务都能转交人工完成，不发生额外损坏、超时或重试，人工能力充足且不反向阻塞机器人，则：

```text
单位成本 = [30 + 114×0.01 + 114×(1−自主完成率)×2×0.5] / 114
```

| 自主完成率 | 每小时转人工任务 | 每小时人工分钟 | 单位合格任务成本 |
|---|---:|---:|---:|
| 95% | 5.7 | 11.4 | 约 0.323 元 |
| 90% | 11.4 | 22.8 | 约 0.373 元 |
| 70% | 34.2 | 68.4 | 约 0.573 元 |

这一组假设下，自主完成率需高于约 87.3%，才低于 0.40 元的基准成本。但这不是行业通用及格线；任务节拍、固定成本、接管时长或损坏率变化，阈值都会变化。

算例还揭示了两个经常被遗漏的约束：

**第一，人工兜底有容量上限。** 自主完成率为 70% 时，每台机器人每小时需要 68.4 分钟人工，一名操作员即使不休息也无法承接。若要求一名操作员的忙碌率不超过 70%，在 90% 自主完成率下，平均容量上界约为 42/22.8≈1.84 台，还没有计入同时失败和远程连接开销。这不是可直接承诺的“一人管两台”。

**第二，早期系统对利用率非常敏感。** 假设任务量降到 57 次/计划小时，固定成本不变，即使自主完成率仍为 95%，单位成本也升至约 0.586 元。机器人长期处于开机状态，不代表产生了足够有效产出。

因此，模型提升的商业价值具有条件性：当它降低接管量并跨过人员配置或成本阈值时，收益可能明显放大；当没有足够任务或设备频繁停机时，模型分数上涨可能暂时无法转化为回报。

### 3.3 通用化应体现为新场景的边际交付成本下降

**中心判断：早期工程适配不可避免，关键在于适配能否沉淀为后续项目可复用的产品能力。**

访谈约  讲述了把仓储项目分解为标准组件，再由配置或集成完成交付的经验。这比“拒绝所有定制化”更准确：现实中的整套系统可能需要集成，但每次交付不应都从头重做。[访谈节目][N-T]

建议把工作划为三层：

| 层次 | 例子 | 管理方式 |
|---|---|---|
| 可复用产品 | 通用策略、硬件接口、数据格式、诊断和恢复模块 | 持续积累，由多客户共同摊销 |
| 可配置交付 | 相机标定、末端选择、动作范围、任务模板与分流规则 | 标准工具和操作流程，记录每次工时 |
| 专项定制 | 客户独有机械改造、独有业务接口、专属模型分支 | 单独报价与核算，判断能否产品化 |

“一脑多形”的价值也应在这里验证。即使共享主模型，不同本体的动力学、传感布局、末端能力仍可能需要标定和适配；收益在于迁移所需数据、工时和验证成本下降，而不是接口能够连接就代表模型已经泛化。

对追求通用能力的公司，可以同时监控两条曲线：**新客户交付工时是否下降；新任务适配数据量是否下降。** 只有前者下降，可能是工程熟练；只有后者下降，可能是模型更强但交付仍昂贵。两者共同改善，才更接近可扩张的具身产品。

组织设计需要服务这一目标。场景团队负责真实约束、故障归因和交付质量；模型团队负责迁移、泛化与回归表现；产品负责人把两边放在同一个任务成本和数据质量框架中协调。否则很容易出现一边追求演示分数，一边靠增加人力兑现交付的错位。

## 四、综合推演：这些论点如何改变产业判断

### 4.1 模型通用化不必然让整条产业链只剩几家公司

访谈中“长期可能只剩个位数公司”属于创业者判断，其成立需要较强前提：跨任务学习收益足够大、数据能够集中、硬件和接口相对标准化，且现场交付不构成长期地域壁垒。[访谈约 ][N-T]

本次更谨慎的推论是：**不同层可能形成不同集中度。** 基础模型与部分工具平台可能受规模效应影响；传感器、执行器、行业服务与现场集成仍可能长期专业化分工。模型市场集中，不等于售后、硬件或应用市场同步集中。

### 4.2 硬件迭代与模型迭代之间可能存在双向增益

硬件一致性改善，可以减少模型需要适应的无关差异，提高数据可复用性；模型更好地处理扰动，又可能降低某些机械精度要求。但反方向也可能成立：复杂模型引入更多计算和能耗，高性能传感器增加维护负担。

所以“软件吃掉硬件”与“硬件决定一切”都不足以解释具身系统。应测量联合优化后的合格任务成本，并确认性能收益不是通过更昂贵工况换来的。

### 4.3 不按年份押注拐点，按可观察的条件判断阶段

将“触觉爆发”“行业低谷”“通用机器人时代”排进确定年份，需要比现有材料更充分的依据。更可用的是条件式情景分析：

| 情景 | 触发信号 | 对企业策略的含义 |
|---|---|---|
| 通用能力快速改善 | 未见任务成功率持续提升，适配数据减少，人工分钟同步下降 | 可逐步扩大任务边界，但每次扩展都重新核算交付成本 |
| 技术缓慢推进、局部任务成立 | 基准增益趋缓，少量任务已有正向经济收益 | 收紧场景边界，强化可配置交付，保护长期研发资源 |
| 模型进步快、工程可靠性落后 | 演示提升，现场可用率、损坏率和维护成本改善有限 | 优先补硬件一致性、诊断和服务体系 |
| 数据学习遇到瓶颈 | 数据量增长而未见任务收益停滞 | 检查数据分布、反馈质量、训练目标与架构，而非只扩数采规模 |

## 五、将金字塔转成可执行的判断框架

### 5.1 对一个具身项目，先获取这六类证据

| 决策问题 | 要求看到的证据 | 对应论点 |
|---|---|---|
| 究竟替客户完成什么？ | 任务边界、质量标准、现行流程成本与任务量 | 生意成立 |
| 身体是否适合？ | 目标工况下的遥操作或工程基线、持续运行与维护记录 | 能力成立 |
| 模型能力有多强？ | 明确版本与数据划分的测试，披露重试、接管和拒绝 | 能力成立 |
| 失败后是否继续交付？ | 恢复和人工转交记录、峰值排队、端到端完成率 | 能力与生意成立 |
| 数据有没有带来改进？ | 同等条件的版本对照、未见样本结果、故障复发率 | 学习成立 |
| 能否复制到下一客户？ | 第二现场部署工时、适配数据、维护成本与复购证据 | 学习与生意成立 |

### 5.2 建议用四道验证门槛推进，而非直接追求部署数量

1. **任务可行：** 在限定对象、环境和工况下，硬件与流程能完成任务，成功标准可测量。
2. **运行可行：** 连续运行中覆盖失败、恢复和接管，确认不会因异常积累导致流程崩溃。
3. **经济可行：** 用真实任务量和完整成本比较替代方案，同时检查客户收益与供应商履约利润。
4. **复制可行：** 在第二现场或新对象集上验证适配成本下降，确认改进具有迁移价值。

每道门槛的数值由具体任务和客户要求确定。“100 台”“1,000 台”“10 小时”可以用作某公司的目标，不能替代这些证据。

### 5.3 最值得继续追问的五个开放问题

- 对目标任务而言，限制交付的是错误频率、错误损失、接管排队，还是设备可用率？哪一项投入回报最高？
- 加入触觉、换末端或改工位，相比扩大模型，哪种方式更便宜地减少失败？
- 世界模型生成的数据，能否在控制总预算后减少真机数据需求，并提升未见条件下的表现？
- 现场故障能否转化为其他客户也受益的训练样本，还是只能通过专属规则修补？
- 新版本模型的能力提升，是否真正让客户减少人工和返工，还是仅让演示更流畅？

这五个问题分别落在能力、学习与生意三个分论点上，可以持续用于复盘新论文、新产品和企业进展，而无需随每次宣传更新整套判断框架。
