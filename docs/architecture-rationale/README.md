## 固定任务

沿用 `docs/harness-architectures/core.py`：读取公告和目录，比较生效日期，形成工单提案，批准后创建，再查询可信字段。公告发布于 9 月 1 日、生效于 9 月 15 日；目录误记为 9 月 1 日。模型由确定性响应替身表示。本文没有真实用户、真实公告和真实模型。

一条连续解释路径是：

1. Harness 主文界定可信任务、观察、提案、批准、资源与验收之间的责任。
2. Agent Runtime 解释任务与运行对象、未知结果和恢复；Codex、OpenHands 等提供各自实现参照。
3. 架构选型在同一工单任务上比较三种控制引擎，再通过本轮反例解释共同业务边界。
4. Mini Harness 保留另一个单动作可运行切片，不把它描述成已经完成多轮真实模型系统。

三种引擎的 72 次共同契约检查是历史实验；本轮 16 次执行是配对反例，两者范围不同。Codex 本轮为固定源码研究，无上游运行实验。

## 配对设计与结果

`run.py` 直接编译加载原有 Python 核心。每次场景用独立临时 SQLite。七组在内存中改变唯一一处规则；操作身份组只改变调用方重试键。原始核心、源码仓库及历史结果不被改写。

| 组 | 唯一干预 | 控制组 → 变体 |
| --- | --- | --- |
| budget | 删除预算上限检查 | 0 次模型替身调用 → 1 次 |
| state_version | 忽略未知状态版本 | 要求迁移、0 张 → 成功、1 张 |
| proposal_contract | 删除提案与可信目标校验 | 拒绝 → 等待；两侧均 0 张 |
| resource_verification | 资源存在即成功 | 检出错误字段 → 误报成功 |
| resource_policy | 删除资源事务内许可检查 | 已撤权写入被拒 → 仍写入 |
| same_key_payload_binding | 删除同键异参检查 | 明确冲突 → 接受，但资源仍是旧参数 |
| cancel_effect_accounting | 有副作用取消简化为普通取消 | 保留影响标志 → 丢掉影响标志；两侧仍 1 张 |
| stable_operation_identity | 重试换一个操作键 | 查询复用已有资源、1 张 → 再创建、2 张 |

第三组不能写成“删除校验就越权创建”：独立批准仍阻止写入。第五组直接调用资源方法，模拟前置检查与提交之间撤权，不是用户认证或真实并发调度。第七组是报告语义干预，资源没有被撤销。故意破坏契约的变体不是候选框架或生产实现。

## 运行

Python 标准库，无额外依赖，不调用模型，不访问网络或真实业务。

```sh
# 在仓库根目录
python3 docs/architecture-rationale/run.py
# 下载公开实验包并解压后
python3 run.py
```

`source-baseline.json` 固定原核心 SHA-256；脚本运行前强制核验，变体的文本替换也必须只匹配一次。公开 zip 附带该核心的原样副本 `core.py`，保留来源路径及哈希。`results.json` 保存实际 Python 版本、每项干预及两侧结果。结果：8 组、16 次执行符合预期。

这只能说明固定输入和干预下的局部因果，不是统计显著性、真实模型效果、生产性能或全部架构正确性的证明。没有运行本轮的 A/B/C 引擎、Codex、外部身份系统、多租户或跨主机故障。要验证采用价值，仍需实际业务约束和真实任务样本。
