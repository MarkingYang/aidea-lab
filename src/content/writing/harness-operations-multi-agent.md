十份资料分别核验，可能适合并行；十个 Agent 同时修改同一篇文章，往往需要先解决协作问题。工作量大，并不自动意味着可以拆成独立任务。

多 Agent 的第一项判断，是新增会话能否带来独立的上下文、专业能力或可并行的工作。角色名称的数量不能证明系统效率。

## 先判断任务能不能独立完成

| 任务形态 | 优先考虑 | 原因 |
| --- | --- | --- |
| 多个互不依赖的资料核验 | 并行只读子任务 | 输入与产物可以隔离 |
| 后一步依赖前一步结论 | 顺序流程或局部委派 | 并行不能消除依赖 |
| 多人修改同一制品 | 分区、版本控制与单点提交 | 防止相互覆盖 |
| 简单查询加固定格式输出 | 单 Agent 或确定性流程 | 委派开销可能更大 |

Anthropic 的研究系统使用协调者与并行子 Agent 探索多个方向，说明多上下文可以服务于广度搜索。这是特定任务中的设计经验，不能直接推导所有业务都应采用相同拓扑。[官方工程案例](https://www.anthropic.com/engineering/multi-agent-research-system)

在资料核验案例中，可让子 Agent 各自核验一个来源并返回证据，把文章更新或工单创建留在统一执行入口。这样先获得并行探索收益，再控制最终写入。

## 委派的是一个有边界的任务

“帮我研究一下”会把任务范围、完成标准和退出条件全部留给子 Agent 猜测。更好的委派需要说明以下内容：

| 委派字段 | 例子 |
| --- | --- |
| 目标 | 核验 source-001 的发布日期 |
| 输入范围 | 指定版本资料与允许读取的公开来源 |
| 产物 | 日期、来源引用、版本、冲突与未知项 |
| 权限 | 只读，不更新知识库或创建工单 |
| 预算 | 独立上限与父任务剩余额度 |
| 完成条件 | 至少取得要求的证据，或明确说明无法取得 |
| 失败与取消 | 返回已取得证据和未完成事项 |

父任务应保留子任务编号、输入快照、委派版本与当前状态。只把子 Agent 的最后一句话拼起来，会丢掉它是否完成、使用哪版资料和哪些内容仍不确定。

## 汇总器不能把冲突变成多数票

三个 Agent 得到同一个日期，可能只是引用了同一篇转载。增加数量不等于增加独立证据。汇总时需要核对来源重合、发布时间、证据级别和引用链。

如果一个来源写发布日期，另一个写功能开放日期，应先区分概念，而不是投票决定哪一个是真的。子任务结果可以按“已证实、冲突、证据不足”汇总，无法解决的差异进入人工核验或下一次有界探索。

已有[记忆治理](/writing/agent-memory-governance/)解释了来源和权限跨团队流动的问题。子 Agent 产物进入共享记忆时也适用：不要因为它来自内部协作，就自动升级为可信事实。

## 并行写入需要显式合并规则

最容易维护的初始方案，是让子任务产出独立草稿或补丁，由一个提交者检查后写入。需要更复杂协作时，可以按文件、章节或资源分区，并用版本前置条件发现冲突。

即使两个子任务没有修改同一行，也可能产生语义冲突：一篇把项目描述为已发布，另一篇仍按预览版解释。机械合并通过以后，仍需整体验收。

[DeepSeek 执行篇](/writing/deepseek-harness-execution/)提供了委派、团队与执行边界的具体案例。本篇建议从“输入隔离、产物独立、提交集中”开始，再用实际协作需求决定是否扩展共享状态。

## 预算与取消需要向下传播

父任务有总预算，子任务有局部上限。并行启动前应预留额度，完成后结算实际消耗；不能让每个子任务都读取同一个未预留余额，然后各自花完它。汇总和独立验收也需要资源。

取消则应记录为持续有效的控制意图。父任务取消后停止新委派，向在途子任务传递取消，并跟踪它们是否停止或仍有外部动作待确认。已经发生的副作用不因取消而消失。

A2A 提供跨 Agent 任务协作的协议对象，MCP 主要连接工具与数据。协议可以帮助交换状态，却不能保证对方已经停止所有外部动作。A2A 规范也说明取消请求不保证成功，需处理任务已结束或当前阶段不可取消等情况。[A2A 规范](https://a2a-protocol.org/dev/specification/)

## 本篇交付物：一次并行收益评审

用单 Agent、并行工具调用、多个 Agent 三种方案完成同一组资料核验。分别记录关键路径、总调用成本、重复检索比例、冲突数量和最终验收结果。

并行工具已能解决的问题，不必增加独立 Agent。多 Agent 确有收益时，再为[工作簿](/labs/harness-operations-workbook.md)中的委派卡补上失联、取消、相互矛盾和父任务预算耗尽四个反例。
