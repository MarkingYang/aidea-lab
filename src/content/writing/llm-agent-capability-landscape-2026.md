> **一句话结论：前沿 LLM 已经“足够聪明”，但 Agent 还没有“足够可靠”。** 2026 年真正值得观察的，不再是谁多拿一个榜单第一，而是谁能在更长、更乱、更接近生产的任务里，以可接受的成本持续交付，并在失败时可发现、可回退、可追责。


> [!NOTE]
> **阅读口径**：本文回答“当前 LLM 与 Agent 到了什么水位、未来会往哪里走”。如果更关心怎样设计结果层、轨迹层和过程层指标，可另读站内的[《Agent 体系评测深度研究报告》](/writing/agent-system-evaluation-research/)。文中优先采用 benchmark 官方榜单与论文；厂商自报、独立评测和多模型系统成绩均单独标注，不混成一张总榜。

截至 2026 年 9 月 4 日，大模型行业同时出现了两幅看似矛盾的画面。

第一幅画面里，模型已经很强。聊天偏好榜前排挤满 Claude、Gemini、Qwen、Kimi、GLM、Muse；代码生成榜频繁逼近饱和；厂商发布页开始用“数小时”“跨应用”“无人值守”描述新模型。

第二幅画面里，Agent 依然脆弱。[Terminal-Bench 2.1 的同模型对照](https://www.tbench.ai/news/terminal-bench-2-1)显示，只因评测集修订，分数就能变化 12.1 个百分点；[Anthropic 的受控实验](https://www.anthropic.com/engineering/infrastructure-noise)显示，基础设施配置还能制造 6 个百分点差异；相关论文的对照结果还显示，从单个 GitHub issue 修复换成长程软件演化，成功率可能从七成档跌到两成档；当任务需要理解不完整需求、处理隐性质量标准或连续遵守业务政策时，顶级系统离“稳定同事”仍有明显距离。

这两幅画面并不冲突。**LLM 的“瞬时能力”已经进入专家工具区，Agent 的“持续交付能力”仍处在工程系统区。** 前者回答“这一刻能不能想明白”，后者回答“连续几十到几百步后，能不能仍把事情做对”。

## 核心判断：当前处在什么水位

如果必须用一句人话给模型与 Agent 定位，我会这样描述：

- **前沿 LLM：像一位知识面极广、反应极快、偶尔自信犯错的专家顾问。** 在明确问题、短反馈回路和可检查输出上，它已经能提供高价值结果。
- **编码 Agent：像一位执行力很强、需要清晰任务单和自动测试保护的初中级工程师。** 它能独立处理一批边界清楚的修复与实现，但还不能稳定承担模糊需求、架构权衡和长期所有权。
- **通用 Agent：像一支擅长检索、调用工具和生成交付物的临时项目组。** 给它充分工具、模型路由和验证器时表现惊艳；拆掉这些外部系统，能力会明显缩水。
- **生产级 Agent：不是一个模型，而是一套受控系统。** 模型只是其中的决策引擎，任务定义、上下文、工具、权限、验证、状态、重试和人工升级共同决定结果。

这也是理解所有排行榜的前提：**今天的 Agent 分数，几乎从来不是“裸模型分数”。**

## 一张图读懂八类评测：它们其实在考不同的东西

| 评测 | 它真正测什么 | 当前最有价值的信号 | 不能推出什么 |
|---|---|---|---|
| Terminal-Bench 2.x / 3.0 / 4.0 | 在终端环境中规划、执行命令、生成可验证产物 | 工具使用、长链执行、恢复能力、单位成功成本 | 不能跨版本直接比较，也不能只归因于模型 |
| SWE-bench Verified | 在真实 Python 仓库修复一个 issue | 明确问题下的仓库级修复基线 | 高分不等于能维护大型系统 |
| SWE-bench Pro | 更复杂、更长程、含私有仓库的软件任务 | 企业级代码任务的难度梯度 | 数据质量争议使绝对分不能照单全收 |
| SWE-EVO | 按 release notes 演化一个项目，跨多文件、多步骤 | 持续规划与长期一致性 | 48 题样本不能外推全部软件工程 |
| Senior SWE-Bench | 需求不完整、性能调查、品味判断 | “像高级工程师一样理解问题”的能力 | judge-based 分数不是纯客观测试通过率 |
| LiveCodeBench | 新鲜竞赛题上的代码生成、自修复与执行 | 算法与代码推理底座，兼顾污染控制 | 不代表 Agent 能理解真实仓库与业务 |
| τ-bench | 对话、知识检索、工具调用与政策遵守 | 企业流程可靠性与多次运行稳定性 | 单次 pass@1 不能等同 SLA |
| GAIA | 搜索、文件处理、推理、工具和模型编排 | 通用助手系统的能力上限 | 排名是 Agent 系统，不是单个模型 |

这张表最重要的信息不是某个分数，而是：**八个 benchmark 不在同一条跑道上。** 把 LiveCodeBench、SWE-EVO 和 GAIA 混成一个“Agent 总分”，就像把百米、马拉松和铁人三项平均后宣布一个人“综合最强”。

## 一、LLM 基本能力：榜首越来越拥挤，名次越来越不值钱

### 1. 聊天体验已经进入“前沿集团”，而不是“唯一王者”阶段

截至 2026 年 9 月 2 日，[Arena Text Overall](https://arena.ai/leaderboard/text/overall-no-style-control) 累计 **7,999,020 票、覆盖 400 个模型**。无风格修正榜前四分别是 Claude Fable 5.1 max **1514±11**、Claude Opus 5 high **1505±5**、Opus 5 max **1505±6**、Opus 4.6 high **1503±3**。

这组数的含义不是“Fable 5.1 确定领先 9 分”。恰恰相反：四者误差区间高度重叠，榜首样本仅 **2,906 票**，第二名有 **35,174 票**。更稳妥的结论是：它们属于同一个前沿密集区，当前顺序会随样本增加而变化。

Arena 还混合了创意写作、对话风格、数学、编码等用户偏好。它很适合回答“人更喜欢和谁聊”，不适合单独回答“谁做生产任务更正确”。这也是为什么一款模型可能在 Arena 很靠前，却在终端、企业政策或长程代码任务里表现完全不同。

开源模型也已经进入可用的前沿邻近区。同一日期的 [Arena 开源筛选榜](https://arena.ai/leaderboard/text?license=open-source) 中，Kimi K3 Max 为 **1489±5、18,090 票**，整体第 12；GLM-5.3 Max 为 **1482±7、7,668 票**，整体第 20。和闭源榜首仍有距离，但已不是“能不能用”的差距，而更像“最困难任务上多花多少成本换多少可靠性”的差距。

### 2. “综合智力指数”本身也正在 Agent 化

2026 年 6 月更新的 [Artificial Analysis Intelligence Index v4.1](https://artificialanalysis.ai/articles/artificial-analysis-intelligence-index-v4-1) 中，GDPval-AA v2 权重 **20%**、Terminal-Bench 2.1 为 **16%**、τ³ Banking 为 **14%**，三项合计正好 **50%**。它们分别考专业交付物、终端执行和企业工具流程。

换句话说，今天看到一个模型“综合智力 66 分”，其中一半权重已经来自模型连同工具和执行框架完成任务的表现。**“基本能力”和“Agent 能力”不再能彻底分开，但研究时仍必须标注底座与系统各自贡献。**

截至 2026 年 9 月 1 日，[Artificial Analysis 对 Claude Fable 5.1 的独立评测](https://artificialanalysis.ai/articles/claude-fable-5-1) 给出：max effort 指数 **66、平均每题成本 3.76 美元**；xhigh 为 **65、2.72 美元**；Claude Opus 5 max 为 **63、2.34 美元**。max 相对 Opus 5 多 3 个指数点，但每题贵约 **61%**。这说明同一个“最强”标签下，其实存在明显不同的经济曲线。

更值得注意的是，Fable 5.1 从 low 到 max 的输出 token 使用量相差 **11 倍**。这意味着 reasoning effort（推理预算）已经像云服务器规格一样成为产品参数：模型名相同，成本、时延与成功率可以完全不同。

### 3. LiveCodeBench 仍重要，但它是“底座体检”，不是“Agent 驾照”

[LiveCodeBench 论文](https://arxiv.org/abs/2403.07974) 的设计价值在于持续从 LeetCode、AtCoder、Codeforces 收集新题，并同时测代码生成、自修复、代码执行和测试输出预测。原始论文包含 **400 道 2023 年 5 月至 2024 年 5 月发布的新题**，目标是降低训练污染并避免只看 HumanEval 一类老题。

它回答的是：模型能否理解算法、生成正确程序并根据反馈修正。它不回答：模型能否读懂数十万行遗留系统、追踪跨服务状态、理解模糊产品需求、控制变更风险。**LiveCodeBench 是发动机台架，不是整车路测。**

## 二、Agent 能力：明确任务进入高分段，长程与模糊任务仍明显掉速

### 1. Terminal-Bench 揭示了 Agent 的真实进步，也揭示了评测有多脆弱

Terminal-Bench 最值得看的不是一条榜，而是 2.0、2.1、3.0、4.0 连续迭代的过程。

[Terminal-Bench 2.1](https://www.tbench.ai/news/terminal-bench-2-1) 修复了 2.0 版 **89 个任务中的 28 个**。在模型和 Harness 不变时，Opus 4.6 + Claude Code 从 **58.0%** 升到 **70.1%**，增加 **12.1 个百分点**；Gemini 3.1 Pro + Terminus 2 从 **63.0%** 升到 **70.7%**，增加 **7.6 个百分点**。变化来自外部依赖漂移、资源不匹配，以及题目描述与测试不一致。

这给所有“新模型领先旧模型 2 分”的新闻一个必要注脚：**若分差小于版本修订与运行环境噪音，它可能没有产品意义。**

2026 年发布的 [Terminal-Bench 3.0](https://www.tbench.ai/news/terminal-bench-3-0) 把难度重新拉开：首版 **74 题、7 个领域**，最佳系统只有约 **34%**。Fable 5 + Claude Code 为 **33.8%**，GPT-5.6 Sol + Codex CLI 为 **34.4%**，能力几乎持平；但后者约便宜 **40%**、输出 token 少约 **50%**。在真实采购中，这个成本差往往比 0.6 个百分点的分数差更重要。

到 2026 年 8 月 28 日，[Terminal-Bench 4.0](https://www.tbench.ai/news/terminal-bench-4-0) 又删除 **8 题**——其中 2 题饱和、2 题触发拒答、2 题已有公开解法、2 题存在质量或兼容问题——并修复 **19 题**，统一为 **8 小时**运行上限。官方明确把这种变更定义为 breaking change，要求所有系统重新跑。

因此，Terminal-Bench 2.1 的高分与 4.0 的低分不能放在同一列计算“模型退步了多少”。**新版分数下降，往往是考卷变难和旧题被淘汰，不是能力倒退。**

### 2. SWE-bench Verified：已经从能力天花板变成回归测试

[SWE-bench 官方榜](https://www.swebench.com/index.html) 显示，原始 SWE-bench 有 **2,294 个实例**；Verified 是其中 **500 个经人工筛选的任务**。当前默认的 Bash Only 视图让所有模型使用相同的 mini-SWE-agent 环境，这比任意提交各带一套 Harness 更利于比较。

Verified 的历史价值巨大：它第一次把“修真实 GitHub issue、在真实仓库跑测试”变成主流模型指标。但当前前沿系统已经把它推向高分区，公开题又带来污染风险。2026 年 7 月，OpenAI 在对代码评测的审计中直言其存在设计与污染问题，认为它已不再提供足够的软件开发能力信号。[这项审计](https://openai.com/index/separating-signal-from-noise-coding-evaluations/) 来自竞争厂商，不能视为中立裁决，但它指出的方向成立：**Verified 更适合做稳定回归基线，不再适合单独决定谁是最强 Coding Agent。**

### 3. SWE-bench Pro：分数涨得很快，考卷质量却成了新瓶颈

[SWE-bench Pro](https://labs.scale.com/papers/swe_bench_pro) 包含 **1,865 个问题、41 个活跃仓库**：11 个公开仓库、12 个 held-out 仓库、18 个商业私有仓库。初始论文在统一 scaffold 下评测时，最佳 GPT-5 只有 **23.3% pass@1**。

截至 2026 年 9 月 4 日，[SWE-bench Pro 公开榜](https://labs.scale.com/api/pdf/leaderboard/swe_bench_pro_public) 的前两名已变成 Muse Spark 1.1 **61.5%**、GPT-5.4 xHigh **59.1%**。相对初始 23.3%，最高公开分增加 **38.2 个百分点**。这确实说明模型与 Agent 系统快速进步，但不能把全部增量归因于底座模型：提交使用的模型版本、推理预算和脚手架并不完全相同。

更大的问题来自数据本身。OpenAI 在 2026 年 7 月审计了 **731 个公开任务**：自动流程标记 **200 个、占 27.4%** 存在严重问题；由资深软件工程师参与的人工标注认定 **249 个、占 34.1%** 有问题，最终估计约 **30%** broken。主要原因包括测试过度限定具体实现、提示缺少隐藏测试要求、测试覆盖不足和提示误导。

这里不应简单站队。Scale 的 Pro 仍比 Verified 更长程、更贴近企业仓库；OpenAI 的审计则提醒我们：**当模型越来越强，评测数据质量会先于模型能力成为上限。** 一个 Agent 失败，既可能是它不会，也可能是题目不可能按说明完成；一个 Agent 成功，也可能是测试漏检。

### 4. SWE-EVO：从“修一个问题”到“演化一个系统”，成功率断崖式下降

[SWE-EVO v6](https://arxiv.org/abs/2512.18470) 只包含 **48 个任务**，但每个任务来自 7 个成熟 Python 项目的 release notes，平均要修改 **21 个文件**，每个实例由平均 **874 个测试**验证。GPT-5.4 + OpenHands 在 SWE-EVO 上只有 **25%**；论文同时给出的对照是 GPT-5.2 在 SWE-bench Verified 上 **72.8%**。

虽然两个对照模型版本不完全相同、48 题样本也偏小，但 **47.8 个百分点**的落差仍然揭示了结构性问题：当前 Agent 擅长把“已定位的问题”修好，不擅长把高层需求分解成多阶段计划，并在大量文件与历史约束之间保持一致。

这正是现实软件工程的主体。企业真正想买的不是“自动修一个 issue”，而是“接住一条业务目标，持续演化一个系统”。从这个标准看，Coding Agent 仍处在能力迁移期。

### 5. Senior SWE-Bench：最难的不是写代码，而是知道“该写什么”

Senior SWE-Bench 专门加入需求不完整、bug/性能调查和“代码品味”判断。官方页面体量较大，这里采用 [BenchLM 对 v2026.06 官方榜的镜像](https://benchlm.ai/benchmarks/seniorswebench)：**100 个长程任务、12 个生产仓库，其中 50 题公开、50 题私有**；榜首 Claude Opus 4.8 的 tasteful solve rate 为 **24%**，Claude Sonnet 5 为 **19.4%**，GPT-5.5 为 **16%**。

这些分数由 taste judge 和 validation agent judge 评分，不等同于纯测试通过率，因此不应和 SWE-bench Verified 直接相减。但它回答了更接近高级工程师的问题：当需求不完整、正确答案不止一种、质量需要判断时，模型能否做出合理选择？当前答案是：**最好系统也只在约四分之一任务上一次做对。**

### 6. τ-bench：企业 Agent 的瓶颈是“连续守规矩”

[τ-bench](https://taubench.com/) 不让 Agent 单纯回答问题，而是要求它和用户对话、检索知识、调用工具、遵守业务政策，并用数据库最终状态验证是否真的完成任务。2026 年 3 月的 τ³ Banking 还加入约 **700 篇文档**的知识库。

截至 2026 年 9 月 4 日，τ³ Banking 的 pass^1 前三是 Qwen 3.8 Max **55.2%**、Claude Opus 5 **48.7%**、Grok 4.5 **47.9%**。这里的“55.2%”不是答对一半银行知识题，而是单次运行中把对话、检索、政策和工具链一起做对的比例。

τ-bench 最重要的设计是 pass^k：同一个任务连续运行 k 次仍全部成功的概率。若单次成功率是 90%，且各次近似独立，连续 5 次全成功只有约 **59%**（0.9⁵）。这就是 Agent 从 demo 到生产的鸿沟：**平均看起来很高的 pass@1，经过长链和重复运行后，会快速折损成不稳定的服务。**

### 7. GAIA：93.36% 很惊艳，但那是“车队成绩”

[GAIA 官方榜](https://gaia-benchmark-leaderboard.hf.space/) 有 **450 多道**需要搜索、工具、文件处理和多步推理的问题，分三级难度，测试答案私有。2026 年 6 月 3 日榜首平均分达到 **93.36%**，三级难题也有 **87.76%**。

但榜首使用的是 Nemotron Tool Orchestrator、GPT-5、Claude Opus 4.1、Qwen2.5-Math-72B 等多模型组合；榜单前排还有大量 Claude、Gemini、GPT 联合系统。官方还说明榜单只展示最佳 run。

所以 GAIA 的正确解读是：**优良的搜索、路由、工具和多模型编排，已经能把通用助手任务做到九成以上；错误解读则是“某个 LLM 的通用智能达到 93%”。** 这是系统工程的胜利，不是裸模型单挑的胜利。

## 三、为什么不同榜单会得出相反结论

把当前评测放在一起，会看到五类常见错觉。

### 错觉一：同名 benchmark 就能跨版本比较

不能。Terminal-Bench 2.1 修复 28/89 题，4.0 又删题、修题、改资源；SWE-EVO 自己也在迭代版本。版本号变化意味着题目分布、验证器或环境变化。跨版本数字只能说明“当时那张考卷上的表现”，不能直接画成模型进步曲线。

### 错觉二：Agent 分数主要由模型决定

不是。[Anthropic 2026 年 2 月的受控实验](https://www.anthropic.com/engineering/infrastructure-noise) 显示，仅 Terminal-Bench 2.0 的资源配置差异就造成 **6 个百分点**分差，且与模型无关的 pod 错误率最高达 **6%**。这已经超过许多榜单相邻名次的差距。

[关于 Harness 的进一步拆解](/writing/anthropic-harness/)也得到相同方向：同一模型、同一任务和同一运行时下，不同 Harness 的通过率和每成功任务成本会显著变化。更稳妥的综合判断是：**Harness 对成本、稳定性和失败恢复影响巨大；模型仍决定能力上限。** 两者不是谁取代谁，而是乘法关系。

### 错觉三：pass@1 高就等于生产可靠

pass@1 只回答“单次尝试能不能成”。生产还要看 pass^k、P95 时延、重试成本、失败是否可发现、错误是否可逆。一次 90% 成功率的 Agent，做 20 个都必须正确的步骤，若近似独立，整条链成功率只有约 **12%**（0.9²⁰）。现实中的错误并不完全独立，但这个计算足以解释为什么长任务会突然崩塌。

### 错觉四：公开榜领先就能复制到私有业务

公开题便于复现，也更容易被训练污染、过拟合和公开解法影响；私有题更接近真实业务，但透明度差、样本少。合理体系必须两者并用：公开集做社区可比性，私有新任务做采购与上线判断。

### 错觉五：厂商发布页、独立榜单和官方公共榜可以混排

不能。厂商自报通常使用最有利的模型设置与 Harness；独立第三方更可比，但也有自己的权重和脚手架；官方公共榜又可能允许各队提交自定义系统。文章或产品若不标“谁跑的、何时跑的、用什么版本和预算”，数字越精确，误导反而越大。

## 四、当前模型格局：没有总冠军，只有三条前沿

### 1. 能力前沿：为最难任务购买更高成功率

Claude Fable 5.1、Claude Opus 5、GPT-5.6 Sol 等高端档位的价值，不是让日常摘要再快一点，而是在失败代价高、任务长、需要多轮验证时，多拿几次成功。

但旗舰也不天然经济。[Anthropic 官方](https://www.anthropic.com/claude/fable) 给 Fable 5.1 的标准价格是每百万输入/输出 token **10/50 美元**，缓存读取降到 **0.25 美元**；官方估计典型工作负载成本降低约 **25%**，高度 agentic 负载最高约 **45%**。Artificial Analysis 的独立实测仍显示其 max 每题成本比 Opus 5 max 高约 61%。缓存降价改善了长程任务，但没有消除高推理预算本身的成本。

### 2. 性价比前沿：Flash、小型旗舰与动态推理预算

市场更大的一条线不是把所有请求送给最强模型，而是“常规任务用便宜模型，困难步骤再升级”。

[OpenAI 2026 年 7 月 30 日价格更新](https://openai.com/index/advancing-the-price-performance-frontier-with-gpt-5-6/) 后，GPT-5.6 Terra 的输入/输出为每百万 token **2/12 美元**，Luna 为 **0.20/1.20 美元**。同一时间，[Gemini 3.8 Flash 模型卡](https://deepmind.google/models/model-cards/gemini-3-8-flash/) 把可调 effort、1M 上下文和生产 Agent 作为核心定位。产品含义非常明确：**高频调用的默认模型将越来越便宜，高成本推理变成按需升级，而非全局常开。**

### 3. 系统前沿：路由、多模型、缓存、验证与并行

GAIA 的前排已经是多模型车队；[OpenAI 的 GPT-5.6 发布页](https://openai.com/index/gpt-5-6/)也把 ultra 的四个并行 Agent 作为默认配置；Artificial Analysis 把缓存 token 和每题成本纳入指数。前沿不再只是预训练参数规模，而是：

> 合适的模型 × 合适的推理预算 × 合适的上下文 × 合适的工具 × 可验证反馈 × 可控权限。

这意味着模型层会继续强，但产品利润和用户体验更可能由系统层拉开。

## 五、市场预期：从“卖聪明”转向“卖完成”

2026 年的指标变化本身，就是市场预期的变化。

过去行业卖的是 token：输入多少、输出多少、单价多少。现在越来越多评测和发布页开始强调 cost per task、time per task、pass^k、缓存成本、工具调用和人工接管。买方真正关心的是“一个合格结果多少钱”，而不是“一个 token 多少钱”。

[Stanford AI Index 2026](https://hai.stanford.edu/ai-index/2026-ai-index-report/technical-performance) 也把前沿模型收敛总结为趋势：当 benchmark 越来越难区分领先模型，成本、延迟、可靠性和领域优化会更影响采用。到 2026 年 9 月，这一判断已从趋势变成产品事实。

未来 12–18 个月，更可能发生的是以下五件事：

1. **模型路由成为默认架构。** 大多数步骤交给低价模型，只有异常、歧义和高价值决策升级旗舰；多模型系统不再是比赛技巧，而是成本控制。
2. **每成功任务成本取代 token 单价。** 失败重试、冗长推理、缓存命中、并行 Agent 和人工返工都会进入同一张账。
3. **Harness 从“胶水代码”变成控制平面。** 上下文压缩、工具权限、状态持久化、验证、重试、审计和人工升级将形成独立产品层。
4. **垂直私有评测比通用大榜更值钱。** 金融、法律、客服、软件工程会用自有流程和失败成本定义评测；公开榜负责发现候选，私有集负责决定采购。
5. **“全自动”会先出现在可验证环境。** 编译、测试、数据库状态、结构化交付物都有明确反馈，最适合放权；开放式战略、组织协调和不可逆操作仍需人类批准。

因此，对“Agent 会不会替代岗位”的更准确回答是：**先替代任务链中的可验证环节，再重组岗位，而不是一次性替代完整角色。**

## 六、技术预期：下一阶段真正要突破什么

### 1. 从单次正确走向长期一致

下一代 Agent 的核心不是再多会一种工具，而是能在数小时到数日任务中保持目标、事实和约束一致。技术重点包括外部状态管理、分层记忆、阶段性总结、独立审计器和失败后恢复。

### 2. 从“模型自评”走向“环境验证”

Agent 说“完成了”没有意义。完成必须对应测试通过、数据库状态正确、文件可打开、指标达标，或人类验收。Terminal-Bench 的 verifier container、SWE-EVO 的大测试套件和 τ-bench 的数据库结果，本质上都在把语言承诺变成可验证状态。

### 3. 从静态榜单走向持续评测

Terminal-Bench 4.0 删除饱和题并采用语义化版本，LiveCodeBench持续加入新题，说明 benchmark 本身也要像软件一样维护。未来高质量评测会具备：新鲜私有题、版本化环境、完整轨迹、重放能力、反 reward hacking、数据质量审计和公开变更日志。

### 4. 从平均能力走向风险分层

同一 Agent 可以在只读检索中高度自治，在写代码时需要测试，在发版和支付时必须人工审批。技术路线不是追求一个统一“自治等级”，而是按操作可逆性、影响范围和证据强度动态放权。

### 5. 从单模型竞争走向“模型—Harness 共进化”

更强模型会吸收部分提示工程、工具选择和上下文管理能力，但权限、审计、验证、状态和人工升级不会消失。它们是组织治理需求，不是模型智力缺陷。未来更成熟的 Harness 会更薄、更标准化，却不会归零。

## 七、企业应该怎样建立自己的评测体系

如果这篇文章只留下一个可执行框架，我建议使用下面的“五层评测”。

| 层 | 固定什么、变化什么 | 必测指标 |
|---|---|---|
| 1. 模型层 | 固定 Harness、任务、预算，只换模型 | pass@1、质量分、token、时延、拒答率 |
| 2. Harness 层 | 固定模型与任务，只换上下文/工具/循环策略 | 成功率增量、重试次数、缓存率、每成功任务成本 |
| 3. 环境层 | 固定模型与 Harness，改变 CPU、内存、网络和超时 | infra error、P95 时延、资源敏感度 |
| 4. 任务与验证层 | 公开基准 + 私有新任务 + 反作弊与人工审计 | 可解率、误判率、隐藏测试覆盖、轨迹完整性 |
| 5. 生产结果层 | 影子运行、灰度和真实用户流程 | 人工接管率、不可逆错误率、SLA、返工时间、业务收益 |

在模型选型上，至少同时报告六个数：

- 单次成功率 pass@1；
- 多次稳定性 pass^3 或 pass^5；
- 每成功任务总成本，失败重试必须计入；
- P50 与 P95 完成时延；
- 人工接管率；
- 越权、错误写入和不可逆失败率。

并坚持三个实验原则：

1. **固定 Harness 比模型。** 否则测到的是整套产品，不是底座差异。
2. **固定模型比 Harness。** 否则永远不知道成本和稳定性来自哪里。
3. **公开榜筛选，私有集决策。** 私有集要来自最近真实失败与真实业务，不要只仿照公开题。

上线顺序也应从可逆到不可逆：离线回放 → 只读影子运行 → 低风险写入 → 审批后高风险写入。Agent 的权限应由证据解锁，而不是由营销文案解锁。

## 结语：真正的临界点，不是模型考满分

截至 2026 年 9 月，我们已经越过“LLM 有没有用”的争论。前沿模型在许多知识、代码和工具任务上都足够创造实际价值；开放模型与低价模型又把这种能力快速商品化。

但我们尚未越过“Agent 可以被无条件信任”的临界点。SWE-EVO 的 25%、Senior SWE-Bench 的 24%、τ³ Banking 的 55.2%，以及 Terminal-Bench 的版本与环境噪音，都在提醒同一件事：**能力不是可靠性，演示不是交付，榜单第一不是生产 SLA。**

下一阶段的胜负手不会只是更大的模型。它会来自更好的任务定义、更可靠的验证、更便宜的路由、更可控的权限、更完整的状态与审计，以及更聪明的人机分工。

真正成熟的 Agent，不是从不犯错的 Agent，而是一个**知道何时继续、何时验证、何时回退、何时把决定交还给人**的系统。
